# Libre AI Schemas And Contracts

## Intended use

Give producers and consumers a shared, verifiable meaning for the data they exchange. Contracts owns canonical schemas, compatibility rules and reference examples; Governance owns portfolio policy and product owners decide their business behavior.

## Existing candidates and limits

Earlier sources contain JSON schemas, API descriptions, reference vectors and TypeScript and Rust projections. These are candidates for reconciliation by exact revision. A stable wire contract or generated type does not prove a working service, a real mission or permission to perform an effect. This documentary candidate admits no SDK release.

## Proposed boundaries

Keep canonical definitions distinct from generated consumer projections. Preserve explicit versions and compatibility expectations. Runtime validation must cover schema conditions that static types cannot express. Contract validity is separate from authentication, authorization, execution confinement and publication authority.

## Activation criteria

Qualify each selected contract or SDK module with its intended consumer, reference vectors and explicit acceptance and refusal cases. Verify generation reproducibility and agreement between runtime validators for the selected scope. A bounded contract or projection can be admitted independently; application integration criteria apply to that integration and do not block the repository’s documentary existence.
