# P02 job contract between the API and the worker

Decision identifier: `urn:libre-ai:decision:2026-10-09-p02-job-v1`.
Status: accepted.
Owner-arbitration: 2026-10-09

## Context

P02 (information watch, `libre-ai/personal-knowledge-workspace`) runs a Bun API
and a separate Rust worker that exchange work through a PostgreSQL job queue
(owner decision Y4). The API enqueues commands; the worker fetches, parses and
records results. That exchange needs a contract both runtimes validate.

`feed-fetch.v1` already exists but does not fit: its refusal codes are
`radar.*`, its item digests are SHA-256 where P02 records BLAKE3, and its limits
(30 s, 5 redirects) are looser than the P02 bounds (20 s, 3 redirects).

## Alternatives

| Alternative | Consequence |
| --- | --- |
| New `p02-job.v1` here, consumed pinned by the product | One authority for the shape; the product vendors it byte-exact at a pinned commit |
| Product-internal schema in the product repository | Faster, but redefines a contract outside the authority (AGENTS.md boundary) |
| Reuse `feed-fetch.v1` | Mismatched codes, digests and bounds; a v2 would be needed anyway |

## Decision

The owner selected a new `p02-job.v1` in this authority on 2026-10-09
(decision Y33). It is registered as a post-lock catalog addition
(`contracts/catalog-post-lock-additions.v1.json`, digest pinned in
`tools/quality/specification-lock.ts`), classified `tenant-private`,
major-versioned. Semantics: `contracts/p02-job-v1/SEMANTICS.md`.

This record admits a catalog entry. It grants no runtime admission and is not a
role verdict on any implementation; conformance is proved in the product
repository against this authority at a pinned revision.
